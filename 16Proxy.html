Proxy Servers

A proxy is a middleman that makes requests on someone else's behalf. A forward proxy stands in front of clients, and a reverse proxy stands in front of servers. Once that's clear, three interview comparisons come up: proxy vs VPN, proxy vs load balancer, and proxy vs firewall.

The idea

What is a proxy server?

Picture it

A small child wants chocolate. They don't go to the shop; they ask mum, whom they trust. Mum goes to the shop, buys it and gives it to them. Mum is the proxy: she makes the request on the child's behalf. The child is the client and the shopkeeper is the server.

  • A proxy server sits between client and server and acts as the intermediary. All requests pass through it.
  • The client and server don't talk to each other directly.
  • One proxy can serve many clients, just as mum handles requests from both her daughter and her son.

There are two types, forward and reverse. As the names hint, they mainly differ in direction.

Type 1

Forward proxy: stands in front of the clients

Often just called a "proxy". When people say proxy without a qualifier, they usually mean this one. A closed network (your computers, an office intranet) sends every outgoing request through the forward proxy. The proxy goes out to the internet, reaches the server, and passes the response back.

  1. C1 (IP 172.1.0.1) asks for google.com.
  2. The forward proxy makes that request using its own IP, 192.3.0.1.
  3. Google sees a request from 192.3.0.1. It has no idea C1 exists.

So a forward proxy hides the client network. No server can talk to the clients directly; it only ever knows the proxy.

Forward proxy

Five advantages, one disadvantage

Advantage How
1 · Anonymity The client's IP and location are hidden. Servers only see the proxy.
2 · Grouping requests If several clients ask for the same thing, the proxy can club them into one outgoing request.
3 · Access restricted content If a site is blocked by location, a proxy in another country (UK, US) makes the request look like it comes from there.
4 · Security and control Every request goes through one place, so you can add rules, e.g. "no social media: block facebook.com" for 100 office machines.
5 · Caching The first client's request for website A is fetched and stored. The next client asking for it is served from the proxy's cache without going out.

The disadvantage: it works at the application level

The network is built in layers (physical, network, transport… up to application). A proxy works at the application layer, so it has to be set up for each application: 10 apps, 10 proxy setups. Tools that work at the packet level (like a firewall, see below) don't have this limit.

Type 2

Reverse proxy: stands in front of the servers

The opposite direction. A company may run many servers (server 1 … server n). No request from the internet is allowed to reach them directly. It goes to the reverse proxy, which forwards it to the right server.

Forward proxy: the server only knows the proxy, not the clients. Reverse proxy: the client only knows the proxy, not the servers.

Reverse proxy

What a reverse proxy gives you

Advantage How
1 · Security / DDoS protection The outside world only knows the reverse proxy's IP, never the servers'. An attacker can only hit the proxy, which can be backed by huge resources and specialist technology.
2 · Caching The first Paris user's request is fetched from the origin and cached. Later Paris users are served from the CDN's cache.
3 · Lower latency Reverse proxies can be placed near users. Together with caching, responses come from nearby instead of from Singapore.
4 · Load balancing With heavy traffic, it spreads requests across servers 1, 2, 3… The major advantage.

Remember for design interviews: a CDN is a reverse proxy. You'll draw CDNs again and again in "design YouTube / Facebook / …" questions.

The one-line difference

Forward vs reverse is about direction

Forward proxy

Acts for clients. Protects the clients: servers can't see or reach them.

Reverse proxy

Acts for servers. Protects the servers: clients can't see or reach them.

Comparison 1 ★ often confused

Proxy vs VPN

Proxy

An intermediary that gives IP anonymity (masks the IP address), and can add caching and logging. It does not encrypt or decrypt your data.

VPN

Much more than a proxy. You install a VPN client, which connects to the provider's VPN server. Everything is encrypted on the way into a VPN tunnel and decrypted at the VPN server. An attacker in between can't read it.

The key difference: a VPN encrypts and decrypts your data and builds a safe tunnel. A proxy only hides your IP.

Comparison 2

Reverse proxy vs load balancer

  • A reverse proxy can act as a load balancer, but a load balancer can't act as a proxy. A proxy also brings anonymity, caching and logging. A load balancer only spreads traffic.
  • One server? You don't need a load balancer; it only makes sense with more than one server. You might still want a reverse proxy, for caching, hiding the server and logging.
Comparison 3

Proxy vs firewall

  • A firewall is a wall with small holes, each with a rule about what may pass between your network and the internet.
  • It does packet scanning: it checks the header, meaning source IP and port, destination IP and port, and allows or blocks by rule. It doesn't need setting up per application.
  • A proxy works at the application level. Beyond ports and IPs it can see the data, so rules can be based on content. But it must be set up per application.
  • Proxies started out as anonymity tools. Today a proxy firewall can also block requests by rule, like a firewall, while still working at the application layer. A traditional firewall works on packets.

Beyond the course good to know as an engineer

Good to know as an engineer

What reverse proxies do in real systems

  • TLS termination: the proxy holds the HTTPS certificate, decrypts requests and forwards plain HTTP to the servers on the private network. That takes the encryption work off the app servers.
  • Compression, rate limiting, auth checks, routing by URL path (/api → API servers, /images → storage). An API gateway is a reverse proxy with these features, and the rate limiter from lecture 12 often lives here.
  • Common software: Nginx, HAProxy, Envoy, Traefik. Managed versions include cloud load balancers and Cloudflare.
  • In microservices, each service can get its own little reverse proxy, a sidecar (e.g. Envoy). A service mesh is many sidecars working together.

Getting the real client IP: X-Forwarded-For

Behind a reverse proxy, your server sees every request coming from the proxy's IP. Proxies add an X-Forwarded-For header listing the original client IP, then each proxy along the way. Clients can fake this header, so only trust the entries added by your own proxies, especially for rate limiting or blocking.

The load balancer nuance

"A load balancer can't be a proxy" holds for layer 4 load balancers, which just forward TCP connections without reading HTTP. Layer 7 load balancers (Nginx, HAProxy, AWS's application load balancer) are reverse proxies. They terminate the connection, read the request and can cache, rewrite and log. In practice the two terms overlap heavily.

Proxies and HTTPS

  • A forward proxy handles HTTPS with the CONNECT method. It opens a tunnel to the site and blindly relays the encrypted bytes. Your traffic stays encrypted end to end by TLS, but the proxy can only see the site's name, not the content. So a modern proxy can't cache or filter HTTPS content unless it's set up to decrypt it.
  • "Grouping requests" is usually called request collapsing: concurrent requests for the same cacheable item wait for one fetch.

The VPN nuance

  • A VPN works at the network layer (e.g. WireGuard, IPsec), so it covers all apps on the device at once. A regular proxy covers only the apps configured to use it. SOCKS5 proxies sit in between: they relay any TCP/UDP traffic, but still don't encrypt.
  • A VPN encrypts only the trip to the VPN server. After that, traffic goes out normally, and the VPN provider can see it. You're moving trust from your ISP to the provider, not removing it.

Firewalls have caught up too

Modern "next-generation" firewalls are stateful (they track connections) and can inspect application data. A WAF (web application firewall) is essentially a reverse proxy that filters HTTP attacks like SQL injection. "Packet vs application" is a good way to explain the classic difference, but real products blend them.

Transparent proxies

The "set up per application" cost applies to explicit proxies. Companies and ISPs also run transparent proxies that intercept traffic at the network level, with no configuration on the client.

Check yourself

Revision questions

Try answering out loud before opening each one.

Define a proxy server in one sentence.

A server that sits between client and server and makes requests on someone's behalf, so the two never talk directly.

Forward vs reverse proxy?

Same middleman, opposite direction. A forward proxy acts for and hides the clients. A reverse proxy acts for and hides the servers.

Five advantages of a forward proxy?

Anonymity, grouping requests, access to location-restricted content, security/control rules, and caching.

Its disadvantage?

It works at the application level, so it has to be set up for each application.

Four advantages of a reverse proxy?

Security (hides server IPs, absorbs DDoS), caching, lower latency (placed near users), and load balancing.

Is a CDN a forward or reverse proxy?

Reverse. It sits in front of the origin servers and serves users from nearby caches.

Proxy vs VPN?

A proxy masks the IP (and can cache and log). A VPN also encrypts the data and sends it through a secure tunnel between the VPN client and VPN server.

Why can a reverse proxy be a load balancer but not the other way round?

Load balancing is just one of a reverse proxy's jobs. A load balancer has none of the others (anonymity, caching, logging). And with one server you need no load balancer, but may still want a reverse proxy.

Proxy vs firewall?

A traditional firewall scans packets: source and destination IPs and ports, against rules. A proxy works at the application level and can look at the data itself, but has to be set up per application.
