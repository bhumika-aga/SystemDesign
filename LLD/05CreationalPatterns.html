01 · Prototype pattern

Copy an existing object instead of building a new one

Use it when you need a copy (clone) of an existing object, especially when creating that object from scratch is expensive. The lecture calls it the simplest of all 23 design patterns.

Like you're five

Drawing a perfect picture takes all afternoon. Photocopying it takes a second, and then you can colour each copy a little differently.

The naive way: the client copies the fields

public class Student {
    int age;
    private int rollNumber;     // private!
    String name;

    Student() { }
    Student(int age, int rollNumber, String name) {
        this.age = age;
        this.rollNumber = rollNumber;
        this.name = name;
    }
}

// in main()
Student obj = new Student(20, 75, "Ram");

// creating a clone of obj
Student cloneObj = new Student();
cloneObj.name = obj.name;
cloneObj.age  = obj.age;
cloneObj.rollNumber = obj.rollNumber;   // ✕ private: can't access

Two problems:

  • Private fields can't be read from outside the class (and there may be no getter), so the client can't copy them.
  • The client must know the class's internals: which of 100 fields to copy and which 2 to skip. That knowledge belongs to the class, not the caller.
02 · Prototype solution

Let the object clone itself

Cloning is the responsibility of the class being cloned. Every class that supports cloning implements one shared Prototype interface with a clone() method. 

public interface Prototype {
    Prototype clone();
}

public class Student implements Prototype {
    int age;
    private int rollNumber;
    String name;

    Student(int age, int rollNumber, String name) { … }

    @Override
    public Prototype clone() {
        return new Student(age, rollNumber, name);  // can see private
    }
}

// in main()
Student obj = new Student(20, 75, "Ram");
Student cloneObj = (Student) obj.clone();
  • Inside the class, private fields are accessible.
  • The class knows itself: which fields to copy, which to skip.
  • The client just calls clone().
03 · Singleton pattern

Only one instance, ever

Use it when a class must have exactly one object, for example one DB connection (or one ATM) that everything shares.

The recipe: make the constructor private so no one else can call new, and expose a static getInstance() method that always hands back the same object. The instance lives in a static field because static members belong to the class, not to any one object.

1 · Eager initialization

public class DBConnection {
    private static DBConnection conObject = new DBConnection();

    private DBConnection() { }

    public static DBConnection getInstance() {
        return conObject;
    }
}

DBConnection conObject = DBConnection.getInstance();

Created when the class loads, whether or not anyone ever uses it.

2 · Lazy initialization

public class DBConnection {
    private static DBConnection conObject;     // starts as null

    private DBConnection() { }

    public static DBConnection getInstance() {
        if (conObject == null) {
            conObject = new DBConnection();
        }
        return conObject;
    }
}

Created on the first call. But it isn't thread-safe:

3 · Synchronized method

synchronized public static DBConnection getInstance() {
    if (conObject == null) {
        conObject = new DBConnection();
    }
    return conObject;
}

Thread-safe, but every call takes the lock, even the 10,000 calls after the object already exists. Locking is expensive, so this is rarely used.

4 · Double-checked locking

public class DBConnection {
    private static volatile DBConnection conObject;   // see note

    private DBConnection() { }

    public static DBConnection getInstance() {
        if (conObject == null) {                        // check 1
            synchronized (DBConnection.class) {
                if (conObject == null) {                // check 2
                    conObject = new DBConnection();
                }
            }
        }
        return conObject;
    }
}

T1 and T2 both pass check 1. T1 gets the lock and creates the object. When T2 gets the lock, check 2 sees the object already exists, so T2 simply returns it. The lecture calls this the version used in industry.

correction The lecture's code leaves out volatile. Without it, the JVM may let another thread see the reference before the constructor has finished (instruction reordering), so it gets a half-built object. Double-checked locking is only correct in Java 5+ with a volatile field.

04 · Factory recap

All creation logic in one place

If 1,000 classes each call new Circle(), then a change to when a circle should be created means editing 1,000 places. A factory keeps that logic in one class. 

public interface Shape { void computeArea(); }
// Circle, Square, Rectangle implement Shape

public class ShapeInstanceFactory {
    public Shape getShapeInstance(String value) {
        if (value.equals("Circle"))         return new Circle();
        else if (value.equals("Square"))    return new Square();
        else if (value.equals("Rectangle")) return new Rectangle();
        return null;
    }
}

ShapeInstanceFactory factoryObj = new ShapeInstanceFactory();
Shape circleObj = factoryObj.getShapeInstance("Circle");
circleObj.computeArea();

Want to stop creating squares? Change one line in the factory, not every class that uses shapes. More detail: lecture 3.

05 · Abstract factory recap

A factory of factories, now for cars

public interface Car { int getTopSpeed(); }

public interface AbstractFactory { Car getInstance(int price); }

public class EconomicCarFactory implements AbstractFactory {
    @Override
    public Car getInstance(int price) {
        if (price <= 300000)     return new EconomicCar1();
        else if (price > 300000) return new EconomicCar2();
        return null;
    }
}
// LuxuryCarFactory: 1000000–2000000 → LuxuryCar1, above → LuxuryCar2

public class AbstractFactoryProducer {
    public AbstractFactory getFactoryInstance(String value) {
        if (value.equals("Economic")) return new EconomicCarFactory();
        else if (value.equals("Luxury") || value.equals("Premium"))
            return new LuxuryCarFactory();
        return null;
    }
}

AbstractFactoryProducer producer = new AbstractFactoryProducer();
AbstractFactory f = producer.getFactoryInstance("Premium");  // luxury
Car car = f.getInstance(5000000);
System.out.println(car.getTopSpeed());

More detail: lecture 3.

06 · Builder recap

Step-by-step creation, now for homes

  • Steps of an AbstractHomeBuilder: createWalls() → createRoof() → createDoors() → createWindows() → build().
  • It's abstract because home types differ: FlatHomeBuilder and DuplexHomeBuilder can override, say, createWalls() and reuse the rest.
  • The builder holds the step logic; the director orchestrates the order (step 1, 2, 3 for one case; 2, 4, 3, 1 for another).
  • Until build(), everything is in the intermediate builder form. The Student builder from lecture 4 works the same way, and its director depends on the abstract builder (dependency inversion).

Beyond the course good to know as an engineer

Good to know as an engineer

Better singletons than double-checked locking

Holder idiom (Bill Pugh): lazy and thread-safe with no locking code, because the JVM initialises a nested class only when it's first used, and class initialisation is thread-safe. 

public class DBConnection {
    private DBConnection() { }
    private static class Holder {
        static final DBConnection INSTANCE = new DBConnection();
    }
    public static DBConnection getInstance() {
        return Holder.INSTANCE;
    }
}

Enum singleton (Effective Java's recommendation): the JVM guarantees one instance and blocks reflection and serialization attacks. 

public enum DBConnection {
    INSTANCE;
    public void query(String sql) { … }
}
DBConnection.INSTANCE.query("SELECT 1");

How hand-written singletons get broken

  • Reflection can call the private constructor. Guard: throw if an instance already exists.
  • Serialization: deserializing creates a new object. Guard: add readResolve() returning the instance.
  • Cloning, and multiple class loaders (each loader gets its own copy).
  • The enum version is immune to the first two.

Singletons: use with care

A singleton is global state: hidden dependencies, hard to mock in tests, and a bottleneck if it holds a lock. Modern code often lets a DI container manage "one instance". Spring beans are singleton-scoped by default, but that means one per container, enforced by the framework, not by a private constructor.

Prototype in real Java

  • Java's built-in Cloneable plus Object.clone() is widely considered awkward: Cloneable has no methods, you must cast, and you must handle CloneNotSupportedException. Many developers prefer a copy constructor: new Student(other).
  • Shallow vs deep copy: copying a reference field (like a List) shares the same list between original and clone, so a change through one shows in the other. Copy mutable fields; immutable ones (String, Integer) can be shared.
  • A prototype registry keeps named, pre-built templates ("basicRobot", "armoredRobot") and hands out copies.
  • JavaScript's whole object model is prototype-based: objects inherit by pointing at a prototype object.
Check yourself

Revision questions

Try answering out loud before opening each one.

What two problems appear when the client copies an object's fields itself?

It can't access private fields, and it has to know the class's internals (which fields to copy and which to skip).

How does the prototype pattern solve them?

The class itself implements clone() from a shared Prototype interface. Inside the class, private fields are visible and the copying rules live with the class.

What two things make a class a singleton?

A private constructor and a static method (getInstance) that always returns the same static instance.

Eager vs lazy initialization?

Eager creates the instance when the class loads. Lazy creates it on the first getInstance() call.

Why is plain lazy initialization not thread-safe?

Two threads can both see null at the same time and each create an object.

What's wrong with a synchronized getInstance()?

Every call takes a lock, even after the object exists, which is expensive.

Why does double-checked locking check twice, and what keyword does it need?

The first check skips the lock once the object exists. The second, inside the lock, stops a waiting thread from creating a duplicate. The field must be volatile so no thread sees a half-constructed object.

What's the abstract factory's "factory of factories" in the car example?

AbstractFactoryProducer returns EconomicCarFactory or LuxuryCarFactory; that factory then returns a car by price.

Shallow vs deep copy?

Shallow copies references, so mutable sub-objects are shared. Deep copies the sub-objects too, so original and clone are fully independent.
