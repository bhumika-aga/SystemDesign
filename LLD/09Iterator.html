Iterator Pattern

Every Java collection stores its data differently (arrays, linked nodes, hash tables), yet you loop over all of them the same way: hasNext() and next(). The iterator pattern is what makes that possible.

00 · Why it's needed

The client shouldn't care how data is stored

Java's collections each store data their own way: ArrayList uses an array, LinkedList uses linked nodes, LinkedHashSet uses a hash map plus a linked list. But when you iterate, you don't need to know any of that. 

public class LinkedHashSetExample {
    public static void main(String args[]) {
        Set<Integer> intSet = new LinkedHashSet<>();
        intSet.add(2);
        intSet.add(77);
        intSet.add(82);
        intSet.add(63);
        intSet.add(5);

        Iterator<Integer> iterable = intSet.iterator();
        while (iterable.hasNext()) {
            int val = iterable.next();
            System.out.println(val);
        }
    }
}

Swap LinkedHashSet for a PriorityQueue or a Stack and the loop doesn't change. How does that work? That's the iterator pattern.

Like you're five

A sweet shop keeps sweets in jars, boxes and bags. You don't rummage through them; you just ask the shopkeeper "next one, please?" until they say "that's all". The shopkeeper knows how each container opens.

01 · Definition

Access elements one by one, without exposing the insides

A behavioural pattern that provides a way to access the elements of a collection sequentially without exposing its underlying representation.

  • Iterator (interface): hasNext() says whether more elements remain; next() returns the current one and moves on.
  • Concrete iterator: implements those two for a specific data structure (array, linked list, tree…). There can be many.
  • Aggregate (interface): something that holds a collection of data and exposes createIterator().
  • Concrete aggregate: the actual collection (ArrayList, PriorityQueue, your own Library…). It decides which iterator to return.
02 · Inside the JDK

ArrayList has its own iterator class

ArrayList contains a private inner class Itr that implements java.util.Iterator using an array index (simplified): 

private class Itr implements Iterator<E> {
    int cursor;                 // index of next element to return
    int lastRet = -1;           // index of last element returned
    int expectedModCount = modCount;

    public boolean hasNext() { return cursor != size; }

    public E next() {
        checkForComodification();
        int i = cursor;
        if (i >= size) throw new NoSuchElementException();
        Object[] elementData = ArrayList.this.elementData;
        cursor = i + 1;
        return (E) elementData[lastRet = i];
    }
}

LinkedList has its own iterators that follow node links (including a DescendingIterator that walks backwards). Each collection writes the logic that fits its data structure, and the client sees the same two methods.

03 · Build one

A library of books

public class Book {
    private int price;
    private String bookName;

    Book(int price, String bookName) {
        this.price = price;
        this.bookName = bookName;
    }
    public int getPrice()       { return price; }
    public String getBookName() { return bookName; }
}

public interface Aggregate {
    Iterator createIterator();
}
public interface Iterator {
    boolean hasNext();
    Object next();
}

The concrete aggregate is the Library. It holds the books and chooses the iterator: 

public class Library implements Aggregate {
    private List<Book> booksList;

    public Library(List<Book> booksList) {
        this.booksList = booksList;
    }

    @Override
    public Iterator createIterator() {
        return new BookIterator(booksList);
    }
}

public class BookIterator implements Iterator {
    private List<Book> books;
    private int index = 0;

    public BookIterator(List<Book> books) {
        this.books = books;
    }

    @Override
    public boolean hasNext() {
        return index < books.size();
    }

    @Override
    public Object next() {
        if (this.hasNext()) {
            return books.get(index++);
        }
        return null;
    }
}
public class Client {
    public static void main(String[] args) {
        List<Book> booksList = Arrays.asList(
                new Book(100, "Science"),
                new Book(200, "Maths"),
                new Book(300, "GK"),
                new Book(400, "Drawing"));

        Library lib = new Library(booksList);
        Iterator iterator = lib.createIterator();

        while (iterator.hasNext()) {
            Book book = (Book) iterator.next();
            System.out.println(book.getBookName());
        }
    }
}

Tomorrow you could add a new aggregate that stores data in a stack or a tree. As long as it implements createIterator() and returns an iterator with hasNext() and next(), this client loop stays exactly the same.

Beyond the course good to know as an engineer

Good to know as an engineer

Make it work with for-each

Implement java.lang.Iterable instead of a custom Aggregate, and Java's enhanced for loop works on your class. Generics also remove the (Book) cast: 

public class Library implements Iterable<Book> {
    private final List<Book> books;
    public Library(List<Book> books) { this.books = books; }

    @Override
    public java.util.Iterator<Book> iterator() {
        return new java.util.Iterator<>() {
            private int index = 0;
            public boolean hasNext() { return index < books.size(); }
            public Book next() {
                if (!hasNext()) throw new NoSuchElementException();
                return books.get(index++);
            }
        };
    }
}

for (Book b : lib) System.out.println(b.getBookName());

Note next() should throw NoSuchElementException when there's nothing left, not return null (lecture 7's problem again).

Fail-fast iterators and ConcurrentModificationException

That modCount check in ArrayList.Itr is there to detect the collection being modified mid-iteration: 

for (Integer x : list) {
    if (x == 2) list.remove(x);   // ✕ ConcurrentModificationException
}

Iterator<Integer> it = list.iterator();
while (it.hasNext()) {
    if (it.next() == 2) it.remove();   // ✓ via the iterator
}
list.removeIf(x -> x == 2);       // ✓ simplest

Concurrent collections such as CopyOnWriteArrayList and ConcurrentHashMap use fail-safe / weakly consistent iterators: they work on a snapshot (or tolerate changes) and never throw. The detection in fail-fast iterators is best-effort, so don't rely on it for correctness.

External vs internal iteration

  • External (this lecture): the client drives the loop with hasNext() / next(). It's flexible, for example stepping through two collections side by side.
  • Internal (Java 8+): you hand over the action and the collection drives: list.forEach(...), list.stream().filter(...). Less code, and easier to parallelise.

One collection, many iterators

Because traversal lives outside the collection, you can offer several orders: forwards, backwards (LinkedList.descendingIterator()), in-order or level-order for a tree, or a filtering iterator. Several iterators can also walk the same collection at once, each with its own position.

Revision questions

Try answering out loud before opening each one.

Define the iterator pattern.

A behavioural pattern that provides a way to access elements of a collection sequentially without exposing the collection's underlying representation.

What two methods does the Iterator interface have, and what do they do?

hasNext() returns whether more elements remain; next() returns the current element and advances.

What's the role of the aggregate?

It holds the collection of data and exposes createIterator(), returning the right concrete iterator for its data structure.

In the lecture's example, which class is the concrete aggregate and which is the concrete iterator?

Library is the concrete aggregate; BookIterator is the concrete iterator.

How does BookIterator know when to stop?

hasNext() returns index < books.size(); once the index reaches the list size, it returns false.

Where does ArrayList implement its iterator?

In a private inner class Itr, which tracks a cursor into the backing array.

Why does removing from a list inside a for-each loop throw?

The fail-fast iterator notices the structural change (modCount differs from expectedModCount) and throws ConcurrentModificationException. Use iterator.remove() or removeIf().

External vs internal iteration?

External: the client calls hasNext()/next(). Internal: the collection loops and calls your function (forEach, streams).
